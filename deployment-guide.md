# Deployment Guide

Use this workflow for FHEVM projects generated by an AI agent.

## Phase 1: Local Compile

```bash
npm install
npm run compile
```

Expected:

- Solidity compiles.
- TypeChain emits types.
- No unknown FHE function names.
- No duplicate contract-name collision.

## Phase 2: Mock Tests

```bash
npm test
```

The default Hardhat network uses mock FHEVM execution. Use it for fast CI and agent feedback.

Validate:

- encrypted input proof flow
- ACL grants
- user decryption
- public decryption
- revert paths
- type correctness

## Phase 3: Persistent Local Node

```bash
npx hardhat node
npx hardhat deploy --network localhost
```

Use this for frontend integration because state persists across browser transactions.

Checklist:

- frontend reads deployment address
- relayer mode matches localhost/mock setup
- wallet chain ID is 31337
- encrypted input uses the deployed contract address

## Phase 4: Sepolia

Zama Protocol is available on Sepolia for real encrypted execution.

Set environment variables:

```bash
set MNEMONIC=...
set INFURA_API_KEY=...
```

Compile and deploy:

```bash
npm run compile
npx hardhat deploy --network sepolia
```

Check compatibility:

```bash
npx hardhat fhevm check-fhevm-compatibility --network sepolia --address <contract>
```

Sepolia readiness checklist:

- mock tests pass
- no plaintext private-state mirror
- all persistent encrypted state has ACL
- frontend uses Sepolia relayer config
- wallet has Sepolia ETH
- gas limits account for FHE operations

## Phase 5: Frontend Validation

Validate these flows manually:

1. Connect wallet.
2. Encrypt input.
3. Submit transaction.
4. Read handle.
5. User-decrypt private value or public-decrypt final result.
6. Refresh page and repeat decryption.
7. Change wallet and confirm unauthorized reads fail.

Also validate the frontend runtime itself:

- Browser console has no top-level module import error.
- Connect Wallet either opens the wallet or writes a clear no-wallet message to the app log.
- Static CDN demos load the Zama UMD bundle through `<script src="...relayer-sdk-js.umd.cjs"></script>` and read `globalThis.relayerSDK`.
- The Vercel deployment serves the latest `app.js`; do not trust a successful deploy if the buttons are inert.

## Phase 6: One-Command Hosted Demo

Use this lane when recording the bounty demo or when a user asks for "build, test, deploy contract, deploy frontend, and give me the URL."

1. Copy `.env.example` to `.env`.
2. Fill:

```bash
MNEMONIC=
INFURA_API_KEY=
VERCEL_TOKEN=
```

3. Keep `DEPLOY_FRONTEND_PROD=false` for preview deployments.
4. Run:

```bash
npm run deploy:demo
```

The command:

- compiles contracts
- runs the full FHEVM test suite
- deploys `ConfidentialVoting` to Sepolia
- writes `frontend/confidential-voting-app/deployment.json`
- deploys the frontend through Vercel CLI using `VERCEL_TOKEN`
- prints the contract address and frontend URL

Do not commit `.env`, `.vercel`, or generated `deployments/` artifacts.

## Deployment Anti-Mistakes

- Do not deploy to Sepolia before local mock tests pass.
- Do not rely on global Hardhat variables for CI; prefer explicit env vars.
- Do not use odd-numbered Node versions with Hardhat.
- Do not skip `check-fhevm-compatibility`.
- Do not assume localhost behavior equals Sepolia real encryption latency.
- Do not pass `VERCEL_TOKEN` to frontend code or any `NEXT_PUBLIC_` variable.
